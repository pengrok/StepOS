## 결정 사항

| 날짜 | 결정 | 이유 |
|---|---|---|
| 11. 21. | 정답은 엔진이 계산하고, LLM은 해석과 설명만 맡음 | 챗봇이 단계별 계산을 틀리는 문제를 막기 위해 (기획서) |
| 11. 21. | Next.js + TypeScript 한 프로젝트로 화면과 서버 API를 함께 둠 | API 키를 서버에만 두고, Vercel에 그대로 배포하기 위해 |
| 11. 21. | 배포는 Vercel만 사용하고 DB는 두지 않음 | 공모전 규모에서는 저장할 데이터가 없음. 설명 재사용은 브라우저 저장으로 처리 |
| 11. 21. | LLM은 GPT와 Gemini 중 미정. AI SDK로 공급사를 바꿀 수 있게 만듦 | 학교 AI 계정 지원 여부가 정해지지 않음 |
| 11. 21. | 규칙 옵션 기본값: 동시 도착은 입력 순서, RR은 새 도착을 큐 앞에, 우선순위는 작은 숫자가 높음·비선점 | Silberschatz·Stallings 교재 관례. 수업과 다르면 팀 확인 후 변경 |
| 11. 21. | 미리보기는 claude.ai 페이지로 공유 | Vercel 배포 전에 링크로 시험해 보기 위해 |
| 11. 28. | AI 문제 해석은 Vercel AI SDK로 Gemini와 GPT를 모두 지원하고, 환경변수로 고름 | 공급사가 정해지지 않음. 키만 넣으면 바로 쓸 수 있게 하기 위해 |
| 11. 28. | AI 사용량 제한은 IP 기준, 메모리 저장 | 로그인과 DB가 없음. 규모가 커지면 공유 저장소로 옮김 |
| 11. 28. | 단계별 해설을 AI 없이 엔진 값으로 먼저 만듦 | 첫 사용에서 "왜 이 프로세스가 실행되나" 질문이 반복됨. 엔진 값으로 만들면 틀리지 않고 비용도 들지 않음. AI는 해설로 답이 안 되는 질문을 맡김 |
